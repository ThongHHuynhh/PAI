Why

  • PAI: session 1 saved the facts to its memory store with the remember tool; session 2 recalled them automatically into one short system block (recall). Its claude-code provider also turns off CLAUDE.md, auto memory and telemetry for each step (env), so each request is small.
  • Claude Code: saved to its auto memory and read the memory index in session 2. It ran with your normal setup (global CLAUDE.md, plugins, MCP servers, skills), which is most of its extra tokens.
  • Codex: no built-in cross-session memory. Run 1 wrote AGENTS.md, but the elevated Windows sandbox wrote it as a separate sandbox user, so the next session could not read it (your own user gets "Access is denied"). Run 2 (unelevated) could not write the file at all and said "Persistent memory isn't available here".

Limits

  • One run per agent: times will vary run to run; token counts are steadier.
  • Codex uses a different model, so its speed and tokens are not a like-for-like harness comparison. PAI and Claude Code both ran Sonnet 5.5.
  • Recall is scored by matching the expected word (5433, atlas, Rust, forge, quartz) in the answer (score).
  • Token split is the same for every agent (tokens). Codex's input_tokens already includes cached input, so it is not added twice.
  • Versions: Claude Code 2.1.312; PAI's pinned claude 2.1.307; codex-cli 0.164.0.
